# 意图缓存与口头表达归一化

`IntentService.classify` 先处理常见确认词，再查询 Redis 意图缓存；未命中时调用意图模型。结果包含意图、槽位和置信度，因此只有归一化后完全相同的输入才会共用结果。

## 已支持的归一化

`UtteranceFingerprint` 对文本归一化后计算 MD5，规则包括：

- 清除代码中列出的中英文标点和空白，统一小写；保留数字之间的小数点。
- 去掉句首的“嗯”“呃”，以及由支持的标点或空白分隔的独立口头禅“嗯”“呃”“那个”“就是说”“就是”。
- 将句首“我想买”“我想要买”“想要买”统一为“想买”。
- 对只有口头禅的输入保留其文本，避免独立的“嗯”与空输入合并。

例如，以下表达使用相同指纹：

```text
我想买手机
想买手机
嗯，我想要买手机。
```

以下差异仍会产生不同指纹：

| 输入 A | 输入 B | 保留的差异 |
| --- | --- | --- |
| 我想买手机 | 我不想买手机 | 否定 |
| 我想买手机 | 我想买电脑 | 商品 |
| 想买两台手机 | 想买一台手机 | 数量 |
| 想买手机预算699.5 | 想买手机预算6995 | 小数点 |
| 想买手机 | 想买手机吗 | 疑问 |
| 那个手机 | 手机 | 无分隔符的指代词 |

这是有限规则下的表达合并，不是通用语义相似度检索。例如“给我推荐一部手机”和“想买手机”不会自动合并。不要全局删除“我”“不”“那个”等字词，否则可能改变意图或商品条件。

## 缓存边界与升级

当前键格式为 `vs:intent_cache:v2:<sessionId>:<fingerprint>`，有效期为 5 分钟。不同会话不共享缓存；`OUT_OF_SCOPE` 结果不写入缓存。命中缓存不会延长有效期。

旧版会删除小数点，使 `699.5` 与 `6995` 发生归一化碰撞。新版使用 `v2` 命名空间，不读取旧的 `vs:intent_cache:<sessionId>:<fingerprint>` 条目；旧条目依照原有 TTL 到期，无需清空 Redis。

键只包含会话 ID 和当前话语指纹，不包含历史对话或槽位版本。依赖上下文的相同话语仍可能命中之前的结果；这次归一化改动没有解决上下文变化引起的缓存失效问题。

## 验证

```bash
mvn -Dtest=UtteranceFingerprintTest,IntentCacheTest test
```

指纹测试覆盖已知等价表达、否定、商品、数量、预算、区域设置和空输入。缓存测试覆盖会话隔离、5 分钟写入 TTL，以及旧版小数碰撞条目的隔离。缓存测试使用模拟 Redis，不能替代真实 Redis 或模型接口的联调验证。
